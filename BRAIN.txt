TASK 2 — clustering, so recurrence is computed rather than typed.

  allocator/cluster.py

    assign_cluster(c: Correction, known: list[str]) -> str

  Given a new correction and the cluster labels already in state.json, return
  either an existing label (same class of correction) or a new short
  kebab-case label. One grok call. Keep the prompt inline in this file — it is
  a utility, not the policy, and it should not live in prompt.txt.

  Then wire it: allocate_and_store(c) looks up the cluster, counts prior
  members, sets c.recurrence from that count, THEN calls allocate().

  This matters more than it looks. Right now `recurrence` is a number a human
  types, which means the weights lane's gate is hand-fed. The demo requires a
  recurrence counter reaching its threshold on camera — "third time you've
  corrected this" is the most convincing frame we have, and it is only real if
  a cluster count produced it.

DONE WHEN
  Three similar corrections fed in sequence through allocate_and_store() produce
  recurrence 0, 1, 2 on the same cluster, the third crosses the threshold and
  routes to WEIGHTS, and state.json reflects all of it.

  Feeding a DIFFERENT correction must not increment that cluster.
